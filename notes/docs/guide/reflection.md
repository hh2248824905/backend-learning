# 学习心得：02 配置管理模块

> 2026-09-16

今天终于把 02 配置管理这个模块学完了，晚上看着 IDEA 里跑通的测试和 Apifox 里自动生成的接口文档，感觉这几天没白熬，写点东西记下来。

## 我学到了什么

这个模块主要就讲了一件事：Spring Boot 怎么读配置。之前只知道 `@Value("${xxx}")` 能把 yml 里的值拿过来，学了之后才发现配置多了这么写太啰嗦了。`@ConfigurationProperties` 直接把一组配置绑到一个类上，连 List、Map、嵌套对象都能接住。我写的 `StudentProperties` 就绑了五种种结构：普通字段、List 爱好、Map 成绩、嵌套的地址、还有对象列表课程，测试跑出来全是 yml 里写的值，那一刻还挺有成就感的。

还有多环境配置。开发环境和生产环境要的配置不一样，以前我以为要复制好几份配置文件，原来只需要 `application-dev.yml` 和 `application-prod.yml`，启动的时候激活对应的 profile 就行，公共的写在主配置里。占位符 `${}` 也比我想的有用，`app.author: ${mxu.name}` 这种写法改一处就全局生效，还能给默认值、取随机数。

## 踩的坑

坑真不少，挑几个印象深的记一下。

最坑的是双启动类。我一开始保留了旧代码，结果项目里有两个 `@SpringBootApplication` 类，`mvn package` 直接报错说找不到唯一主类。后来在 pom 里手动指定了主类才打包成功。而且这两个启动类扫的包不一样，用旧的那个启动，新写的配置类根本注入不进来，一开始我还以为是代码写错了，查了半天。

第二个是看测试输出。第一次跑测试满屏红字警告，吓一跳，以为失败了。其实最后一行写着「退出代码为 0」，就是成功了。那些警告是 Mockito 和 JDK 21 的事，不影响结果。以后先看退出代码，别被红字唬住。

第三个特别蠢：我在命令行用 `java -jar` 验证新接口，一直 404，排查了半天，发现是我改完代码只跑了 test 没有重新 package，跑的还是旧 jar。改了代码必须重新打包，这个低级错误就犯这一次吧。

后来按作业要求给 `AppProperties` 加了 email 和 create-date 两个属性，分别用 `@Email` 和 `@Past` 校验。故意传了个错误邮箱和 `2099-01-01` 的未来日期启动，应用直接 `APPLICATION FAILED TO START`，报错里写清楚是哪个属性、值从哪来、为什么不行。这让我真正体会到「fail-fast」的意思：错误在启动那一秒就暴露，而不是上线之后。另外发现 `LocalDate` 不用任何转换，yml 里写 `2024-09-01` 就能直接绑上去，比想象中省事。

## Apifox 那一步

接口写完之后在 IDEA 里右键上传到 Apifox，文档自动就生成了，连返回对象里嵌套的 Address、Course 都画出来了，字段和代码一一对应。以前觉得写接口文档很麻烦，现在发现根本不用手写，代码改了重新传一次就行。这个习惯我打算保持下去，以后每写完一个 Controller 都传一次。
