**三条主干**：

1. **配置主干**（01 → 02 → 03 → 04 → 05 → 06 → 12）—— 一条完整的「能用的后端服务」，中间任何一环跳过都会卡
2. **异步主干**（06 → 07 → 08 → 09）—— 服务能用了之后，处理并发、定时、权限
3. **交付主干**（04 → 10 → 11 → 13）—— 对外提供文件和文档、对内提供监控

## 2. 六个阶段

| 阶段 | 模块 | 目标 | 判断学会了的标准 |
|---|---|---|---|
| **一、跑起来** | 01 | 知道一个 Spring Boot 项目由什么组成 | 能不看教程从零建一个 Web 项目并返回 JSON |
| **二、配起来** | 02 | 配置可读、可分环境、可校验 | 能说清 `@Value` 和 `@ConfigurationProperties` 各自什么时候用 |
| **三、看得见** | 03 · 04 | 日志分级 + 请求全流程可追踪 | 接口报错时能从日志定位到具体哪一行 |
| **四、存得住** | 05 · 06 · 12 | CRUD 打通 + 有测试兜底 | 能写一个带分页查询和单元测试的完整接口 |
| **五、扛得住** | 07 · 08 · 09 | 异步、定时、权限 | 能说清什么业务该丢队列、什么该用定时任务 |
| **六、交得出** | 10 · 11 · 13 | 文件、文档、监控 | 项目能交给别人维护，有文档有健康检查 |

## 4. 学习节奏建议

**一个模块的完整闭环**（约 4 步，缺一不可）：

1. **看视频 / 读文档** —— 知道要解决什么问题
2. **写代码** —— 落到 `E:\houduan\0X-xxx` 模块里，不是随手建个 demo 文件
3. **跑起来验证** —— 启动服务或跑测试，拿到真实输出
4. **写笔记** —— 把「为什么这么做」和「踩了什么坑」补上，然后 `git push`

::: warning 第 4 步最容易被跳过
跳过写笔记的后果是：一周后你只记得「我做过」，记不得「为什么这么做」。等到第 06 模块需要回头改第 02 模块的配置时，得把整个视频重看一遍。

**一个折中**：哪怕只写三行，也要写「这个模块解决什么问题」「卡在哪」「怎么解决的」。完整笔记可以后补，这三行不补就永远丢了。
:::
