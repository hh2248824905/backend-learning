# 课程总览

本页说明这套笔记覆盖什么、用什么技术栈、怎么组织，以及为什么不直接抄官方文档。

## 1. 什么是「前后端工程化」

写代码和做工程是两件事。会用 `@RestController` 写个接口，不等于能把接口**管起来**：配置怎么分环境、日志怎么分级、异常怎么统一处理、接口文档怎么自动生成、上线后怎么监控。

「工程化」就是把这些**重复出现、必须标准化**的事情固定下来。

| 层面 | 会用（写代码） | 工程化（做系统） |
|---|---|---|
| 配置 | 写死 `port: 8080` | 主配置 + 多环境覆盖 + 外部注入 + 校验 fail-fast |
| 日志 | 到处 `System.out.println` | 日志门面 + 分级 + 分环境 + 滚动归档 |
| 接口 | 一个 Controller 一堆方法 | 分层（Controller/Service/Mapper）+ 统一返回体 + 统一异常 |
| 文档 | 手写 Markdown 维护 | 注解生成 OpenAPI，代码即文档 |
| 质量 | 手动点一遍 | 单元测试 + 集成测试 + 覆盖率 |
| 运维 | 重启看日志 | Actuator 健康检查 + 指标 + 优雅停机 |

这套笔记就是按这六个层面，一个模块一个模块推进。

## 2. 技术栈与版本

前后端两侧都是「**主流 + 最新稳定**」，不追 beta，也不锁老版本。

| 侧 | 技术 | 版本 | 说明 |
|---|---|---|---|
| 后端 | JDK | 21（编译目标 17） | 本机 JDK 21，父 pom 里 `java.version=17` |
| 后端 | Spring Boot | 3.5.16 | 父 pom 继承 `spring-boot-starter-parent` |
| 后端 | 构建工具 | Maven 3.9.16 | 多模块，父工程统一管版本 |
| 后端 | 校验 | Jakarta Validation (Hibernate Validator 8.0.3) | `@Validated` + `@NotBlank/@Min/@Max` |
| 后端 | 工具库 | Lombok 1.18.46 | `@Data` 消除 getter/setter |
| 前端 | 运行时 | Node.js 22 | Vite 8 要求 Node ≥ 20 |
| 前端 | 框架 | Vue 3.5 | 组合式 API `<script setup>` |
| 前端 | 构建 | Vite 8 | 秒级冷启动 |
| 文档 | 静态站点 | VitePress 1.6 | 就是你正在看的这个站 |

::: tip 版本为什么要写清楚
笔记里的报错信息和行为强依赖版本。比如 `spring-boot-starter-parent` 3.2 之后 `@ConfigurationProperties` 的松散绑定行为、Vite 5 升 8 的配置项变动，跨版本照抄会踩坑。写清版本，出问题时有据可查。
:::

## 3. 两个仓库如何分工

前后端是两个**完全独立**的 Git 仓库，互不依赖，各自能单独跑起来。

```
E:\
├── houduan\        → github.com/hh2248824905/backend-learning   (Spring Boot)
│   ├── 01-quickstart\     快速入门
│   ├── 02-config\         配置管理
│   ├── 03-logging\        日志
│   ├── ...                04~13
│   └── pom.xml            父工程，聚合所有子模块
│
└── qianduan\       → github.com/hh2248824905/frontend-learning  (Vue 3)
    ├── 01-vue-literal\    CDN 方式入门，无构建工具
    └── vue-app\           Vite 工程化项目
```

**为什么分两个仓库而不是 monorepo**：前端跑 `npm`、后端跑 `maven`，工具链毫无交集；分仓库后各自的 CI、依赖、提交历史都干净，也不会出现「改前端却触发后端构建」这种浪费。

**代价**：跨端联调时（前端请求后端接口）需要在两个目录间切换。这是可接受的，因为联调阶段本来就得两边同时开。

## 4. 笔记怎么组织

四大部分，和目录结构完全对应：

| 部分 | 路径 | 内容 |
|---|---|---|
| **开始** | `/guide/` | 路线、规划、环境、规范 —— 先看这些 |
| **后端** | `/backend/` | 01~13 模块，一个模块一篇（02 因内容多拆成 4 篇） |
| **前端** | `/frontend/` | HTML/CSS/JS 基础 → Vue 3 → Vite 工程化 |
| **工程化** | `/engineering/` | Maven、Git、IDEA、踩坑记录 —— 跨模块的通用技能 |

## 5. 每篇笔记的固定结构

为了保证质量稳定，所有模块笔记按统一骨架写：

```md
# 0X 模块名

<NoteStatus level="..." />

## 0. 本篇要解决的问题        ← 3~5 条，明确边界
## 1. 核心概念               ← 是什么、为什么需要
## 2. 代码实现               ← 真实源码 + 关键行解读
## 3. 运行验证               ← 命令 + 真实输出（不是"应该会输出"）
## 4. 与相邻知识点的对比      ← 和上一个模块、和替代方案的区别
## 5. 踩过的坑               ← 具体报错 + 原因 + 解法
## 6. 小结与自检清单          ← 能回答的问题列表
```

第 3 节是硬性要求：**没有真实运行输出，这篇笔记不算写完**。这是区分「学习笔记」和「文档摘抄」的唯一标准。
